# Community Guide

The Motech Audit Solidity Security Lab is an open educational project for Solidity developers, security researchers, testers, and technical writers.

You do not need to be a professional auditor to contribute. We value small, verifiable improvements as much as larger research examples.

## Ways to participate

- **Documentation:** explain a vulnerability, mitigation, test, or tool output in clear language.
- **Testing:** add Foundry unit tests, edge cases, fuzz properties, or regression tests.
- **Security research:** propose a focused vulnerability demonstration with a reproducible test and a clearly scoped mitigation.
- **Tooling:** improve CI, static-analysis workflows, developer setup, or result interpretation.
- **Review:** read an open Issue or Pull Request and leave specific, respectful technical feedback.

## How to get started

1. Browse the [open Issues](https://github.com/MotechAudit/motech-solidity-security-lab/issues).
2. Start with an Issue marked `good first issue`, or propose a narrowly scoped task.
3. Comment on the Issue before beginning. Maintainers can confirm scope and help avoid duplicate work.
4. Submit one focused Pull Request and explain what changed and how it was verified.
5. Respond to review feedback and update the Pull Request as needed.

For repository setup and the Pull Request checklist, read [CONTRIBUTING.md](../CONTRIBUTING.md).

## What happens after a contribution is merged?

- The contribution becomes part of the public repository history.
- Externally authored merged work can be listed in [CONTRIBUTORS.md](../CONTRIBUTORS.md), with a link to the original Pull Request.
- Motech Audit may highlight merged work in project updates. A contributor's public handle will be credited accurately; we will not imply endorsement, employment, partnership, or certification.
- There is no standing bounty or payment programme at this time. Any future paid reward will be stated explicitly on the relevant Issue before work begins.

## Community standards

Be constructive, patient, and specific. Critique code and reasoning, not people. Welcome beginner questions and respect different experience levels.

Do not submit client code, private audit reports, non-public vulnerability details, secrets, API keys, or credentials. For security-sensitive reports, follow [SECURITY.md](../SECURITY.md), not a public Issue or Pull Request.

## Scope

This repository is an educational lab. A merged example, passing test, or static-analysis run is not a certification, a production-ready implementation, or a guarantee that a contract is secure.
